Now give my galaxy a brain — I want to type a question and get an answer from MY notes.

— Crie config.json na raiz do projeto (NÃO dentro de viewer/ — ele nunca deve ser acessível pelo navegador) com placeholders: {"api_key": "PUT-YOUR-KEY-HERE", "model": "SEU-MODELO"}. Eu mesmo colarei minha chave de API nesse arquivo — não me peça por ela. — Adicione um endpoint POST /chat em server.py: pontue cada nota em relação à minha pergunta por sobreposição de palavras-chave (correspondências de título têm peso extra), pegue as 6 melhores e chame a API de mensagens do modelo configurado no config.json com um prompt de sistema que diga: responda APENAS com base nessas notas, em 2–3 frases, e admita quando as notas não cobrirem o assunto. — O endpoint retorna {"answer": "...", "nodes": [índices das notas usadas]}. — Mantenha um histórico de conversa curto por sessão no servidor para que perguntas de acompanhamento funcionem. — Adicione uma barra de entrada elegante na parte inferior do visualizador que exibe a resposta na tela. — A chave de API nunca deve aparecer no navegador, no HTML ou em qualquer arquivo que o servidor sirva. — Quando terminar, reinicie o servidor e me dê 3 perguntas de exemplo para testar com base nas minhas notas reais.

Depois: cole sua chave de API no config.json, recarregue o Chrome com força e interrogue seu próprio cérebro. Sem chave de API? Diga ao assistente: "em vez de chave de API, faça /chat usar o modo headless (claude -p) com minha assinatura." Mais lento, mas gratuito.
